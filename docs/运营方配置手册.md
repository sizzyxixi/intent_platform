# 运营方配置手册

> 读者：**你**——在控制台配置业务空间、意图、知识库、工具和 API Key 的人，或持有写权限、要替运营写入意图 / 知识的维护型 AI。
> 使用方（Bot / 业务系统）如何拉配置、识别、检索和调用工具，见同目录《使用方接入指南》。字段细节以 `openapi.yaml` 为准。
> 本文菜单名称、按钮文案与接口路径均按当前生产控制台与代码核对，生产地址：`http://intent.47.86.15.93.sslip.io`。文档里的 `ipk_xxx` 只表示格式，不是能用的密钥。

## 结论

- 配置工作以**控制台登录会话**（`/api/admin`）为主。左侧菜单是「意图管理」「知识库」「工具中心」；管理员在左下角还有「用户与审计」。
- API Key（`/api/v1` 和 MCP）能做的写操作**只有一部分**：草稿意图的批量写入 / 有限字段更新、槽位增改、识别阈值（慎用）、知识导入和切片编辑。**分类层级、意图启用、工具注册、意图绑定工具和知识、创建知识库、删除数据、Key 管理都不对 API Key 开放。**
- 新空间按第 1 节清单走完，再把只读 Key 交给使用方。
- 西之月 xclaw-cli 工具的批量登记没有控制台按钮，要在服务器上跑命令。平台目前不能给空间配置默认店铺 ID。

| 只读 | 只能查看与测试（测试写工具还需勾选确认） |

页面：

## API Key 能写什么、不能写什么

鉴权：`Authorization: Bearer ipk_xxx`。空间范围：绑定了空间的 Key，只能在这些空间上操作意图 / 槽位 / 运行时配置；知识库与工具接口是全局的。权限字面量：`意图:读`、`意图:写`、`知识:读`、`知识:写`、`工具:读`（没有「工具:写」）。

**API Key 可以（`/api/v1` 或同等 MCP）：**

| 能力 | 所需权限 | 接口或 MCP | 限制 |
|---|---|---|---|
| 读空间、运行时配置、意图、槽位、识别设置 | `意图:读` | `GET /spaces`、`/runtime-config`、`/intents`、`/intents/{code}`、`/slots`、`/recognition`；MCP `list_intents` / `get_intent` | 只读已绑定空间 |
| 批量写入意图 | `意图:写` | `POST /intents:batchUpsert`（`mode=merge`）；MCP `upsert_intents` | **写入状态一律是「草稿」**，不会自动启用，也不改工具绑定、知识关联、启用状态 |
| 修改单条意图的有限字段 | `意图:写` | `PATCH /intents/{code}` | 只能改 `name`、`description`、`priority`、`examples`、`negative_examples`、`slot_bindings` |
| 增改删槽位 | `意图:写` | `POST /slots`、`PUT /slots/{name}`、`DELETE /slots/{name}` | 被意图使用的槽位不能删，返回 409 `SLOT_IN_USE` |
| 改识别阈值 | `意图:写` | `PUT /recognition` | 直接改线上配置版本，**慎用** |
| 列知识库、读文档和切片、检索 | `知识:读` | `GET /kbs`、`/kbs/{id}/documents`、`/kbs/{id}/chunks`、`POST /kbs/{id}/search`、`GET /imports/{id}`；MCP `search_knowledge` | REST 没有跨库检索，跨库用 MCP；没有单独的 `GET /kbs/{id}` |
| 导入知识、改切片 | `知识:写` | `POST /kbs/{id}/documents:import`（multipart）、`PUT /kbs/{id}/chunks/{chunk_id}`；MCP `import_knowledge` | **不能新建知识库**，目标库必须已存在。写接口需带 `Idempotency-Key` |
| 列工具、下载技能包 | `工具:读` | `GET /tools`（可 `source=external` / `builtin`）、`GET /tools/{name}/skill-package`；MCP `list_tools` | 开放接口没有单条 `GET /tools/{name}`；不能注册、修改、删除工具 |

**API Key 做不到（必须登录控制台，走 `/api/admin` 会话）：**

- 新建 / 修改业务空间
- 调整分类层级、新增或改分类节点
- 把意图从草稿改为启用（或停用、归档）
- 给意图绑定或解绑工具、关联或取消知识
- 删除意图（槽位可以用带 `意图:写` 的 Key 删除，但被意图占用时会失败）
- 新建或删除知识库、删除文档
- 注册 / 修改 / 删除工具，登记 MCP 服务，同步 MCP 工具，上传技能包
- 测试调用（真实执行）
- 创建、吊销 API Key
- 用户管理、审计日志查询

不要把管理后台接口当成开放接口去调。`POST /api/admin/spaces/{id}/test` 是控制台的单句识别测试，不接受 API Key。

## 1. 新业务空间初始化清单

下面按控制台真实路径列出。全部做完再把只读 Key 交给使用方。

1. **新建空间**（管理员）：意图管理顶栏「＋ 新建空间」，填写：空间 ID（小写英文，创建后不可改）、意图编码前缀（1～4 位大写字母）、名称、描述、对应 Bot / 智能体。新空间的意图、分类、槽位、导入记录、运行时配置和版本都独立；知识库和工具全平台通用。新空间默认层级为「大类 / 问题桶 / 意图」，并带一个「通用 / 默认」分类。接口：`POST /api/admin/spaces`。
2. **按业务调整分类层级**：意图管理 › 空间设置 ›「分类层级」（最多 5 层分类 + 最末层意图）。插入或删除会弹出「影响预览」，确认后配置版本 +1。再在「分类」里新增、改名。接口：`POST /api/admin/spaces/{sid}/levels/preview`、`PUT …/levels`、`POST/PATCH/DELETE …/categories`。
3. **维护槽位**：意图管理 › 槽位。先定义本空间要用的槽位（名称、类型、是否必填、追问话术）。不向用户追问的槽位，把 `ask` 写成「（不向买家追问：…）」这类说明。
4. **登记或确认工具**：工具中心 › 工具目录。平台已登记内置工具和西之月快照中的命令 / 技能。新的 HTTP / CLI / MCP / 工作流 / 技能按第 5 节注册。写操作打开「需确认」。
5. **写意图**：意图管理 › 意图列表 ›「＋ 新建意图」，或用带 `意图:写` 的 Key 走 `POST /api/v1/intents:batchUpsert`（结果是草稿）。填写描述、标准例句、反例、槽位绑定。
6. **绑定工具和知识**：在意图详情里关联工具（先搜索再选择，不要一次加载全部工具）并填写 `param_map`；关联知识库 / 文档 / 切片，区分「参考」和「校验」。这两步**只能在控制台做**。
7. **导入或撰写知识**：知识库 › 导入文档；或先「＋ 新建知识库」。导入后在知识库详情校对切片，用「知识库检索」试查。把校验类切片关联到意图。
8. **启用前验证**：意图详情「验证」，以及空间内的单句测试。通过后再把意图改为「启用」（配置版本 +1，使用方下次拉取才会看到）。
9. **发 Key**：工具中心 › 接入与密钥 ›「＋ 新建 Key」。使用方一般只需只读三项，并绑定本空间。完整 Key 只显示一次，写入对方约定位置（环境变量 `INTENT_PLATFORM_API_KEY` 或 `~/.intent-platform/config.json`，权限 600）。需要 AI 代写草稿意图或导入知识时，另建一把带相应写权限的 Key。
10. **把《使用方接入指南》交给使用方**，说明空间 ID、是否依赖西之月登录、会话里如何注入店铺 ID 等运行参数。
11. **抽查线上**：用使用方的只读 Key 调 `GET /api/v1/spaces` 和 `GET /api/v1/runtime-config`，确认已启用意图和绑定工具出现在配置里。

## 2. 空间、分类与识别设置

空间设置页除分类外，还可改识别阈值、候选下限、最多候选数、澄清次数、槽位追问次数、工具重试次数、最终动作（转人工 / 通用助手 / 拒绝）及拒绝文案。改这些会提升配置版本。

控制台：`GET/PUT /api/admin/spaces/{sid}/recognition`。API Key 也可用 `GET/PUT /api/v1/recognition`（写需要 `意图:写`），因为直接影响线上，改之前要确认业务已同意。

运行时配置预览：控制台 `GET /api/admin/spaces/{sid}/runtime-config`（会话）；使用方用 `GET /api/v1/runtime-config`。

## 3. 意图与槽位

- 意图编码由空间前缀 + 分类路径生成，创建后不要随意改。
- 状态：草稿 → 启用 → 停用 / 归档。只有「启用」会进入运行时配置。状态变更：控制台 `POST /api/admin/intents/{code}/status`。
- 例句要覆盖用户的真实说法；反例用来避免误识别。
- 槽位绑定决定识别后要收集哪些信息，以及工具 `param_map` 从哪取值。
- 验证：`POST /api/admin/intents/{code}/validate`；单句测试：`POST /api/admin/spaces/{sid}/test`（会话，不是 API Key）。
- 批量导入：意图管理 › 导入记录，先预览再应用。`POST /api/admin/spaces/{sid}/imports/preview`、`…/imports/apply`。
- 用 API Key 写入时用 `mode=merge`，只创建或更新为草稿；不要假定它已经启用或已经绑上工具。

## 4. 知识库

知识库全平台通用。页标题是「AI知识库」。

- 新建知识库、改元数据、看删除影响、删除库或文档：仅控制台（`POST /api/admin/kbs` 等）。API Key **不能**创建知识库。
- 导入：控制台「导入文档」，或 API Key `POST /api/v1/kbs/{kb_id}/documents:import`（`知识:写`）。导入是异步的，用返回的任务 ID 查进度。
- 切片：导入后务必人工校对。控制台与 API Key 都是 `PUT …/kbs/{kb_id}/chunks/{chunk_id}`（API Key 路径为 `/api/v1`）。
- 检索试查：知识库 › 知识库检索，或 `POST /api/v1/kbs/{kb_id}/search`。
- 把切片或整篇关联到意图，只能在意图详情里做。校验类知识会出现在运行时配置的 `validation_sets`。

当前 cs 空间已关联的规则类知识库包括回复规则、置信与澄清、询价规则等（以控制台为准）。删除知识库前先看「影响」，避免把已启用意图的校验知识拆掉。

## 5. 工具中心

工具目录默认每页 20 条，可改为 50 / 100；搜索和筛选在服务端执行（当前登记量约七千条，主要是西之月 CLI）。给意图绑工具时也是先搜索再选。

- **注册工具**：工具目录「＋ 注册工具」。类型包括 CLI、HTTP、MCP、工作流、技能。写操作打开「需确认」（`confirm_required`）。保存后可再编辑。接口：`POST/PUT/PATCH/DELETE /api/admin/tools`。
- **MCP 服务**：在工具目录「＋ 注册工具」中选择类型 MCP，登记服务本身；保存后同步 `tools/list`（预览再应用）。意图只关联其中的具体工具，不能整体关联一个服务。接口：`GET/POST /api/admin/mcp-servers`，`POST /api/admin/mcp-servers/{name}/sync/preview` 与 `…/sync/apply`。
- **技能包**：上传 zip，平台按包内 SKILL.md 登记。`POST /api/admin/skill-packages`。
- **西之月 xclaw-cli 批量导入**：控制台**没有**「从西之月导入」按钮。在部署环境执行 `python -m app.westmonth import`（快照在 `backend/seed/westmonth/`）。查看状态用 `python -m app.westmonth status`。官方目录见 https://open.westmonth.com/cli 。
- **测试调用**：工具详情「测试调用」。管理员可真实执行；写工具必须勾选确认。CLI 工具依赖运行环境已安装并登录对应 CLI（生产服务器上的 `xclaw-cli` 若尚未 `auth login`，测试调用会失败，这是环境问题，不是工具登记错误）。接口：`POST /api/admin/tools/{name}/test`。

平台只登记调用方式，不代使用方在线上执行，也不下发第三方密钥。

## 6. 把工具和知识绑到意图

在意图详情中完成：

- 关联工具，为每个入参指定 `param_map`：来源为槽位 / 常量 / 上下文。必填入参必须能取到值，否则使用方按规则不会调用。
- 关联知识，标记参考或校验；校验可指定整篇（`chunk_id="*"`）。
- 改绑定会提升配置版本。这两项没有开放给 API Key 的写接口。

## 7. API Key 管理

仅管理员。路径：工具中心 › 接入与密钥 ›「＋ 新建 Key」（弹窗标题「新建 API Key」）。

- 填写名称、绑定空间、权限。绑定空间只约束意图 / 槽位 / 运行时配置；知识与工具仍是全局可读（在具备对应读权限时）。
- 完整 Key 只显示一次，前缀 `ipk_`。之后列表只显示提示（如 `ipk_ak_xxxx_••••••••`）。
- 吊销：列表中操作，之后该 Key 返回 401 `KEY_REVOKED`。接口：`GET/POST /api/admin/api-keys`，`POST /api/admin/api-keys/{kid}/revoke`。
- 给使用方：只读三项 + 绑定其业务空间，并告知《使用方接入指南》第 1 节的存放约定。
- 给维护型 AI：按需加 `意图:写` / `知识:写`，并说明第 0 节的能力边界（只能写草稿、不能启用、不能绑工具）。

本页同时提供文档下载：使用方接入指南、运营方配置手册，以及索引《AI使用说明》、OpenAPI。

## 8. 用户与审计

左下角「用户与审计」（仅管理员）。

- 用户：新建控制台账号，角色为管理员 / 编辑 / 只读；可改角色、停用、重置密码。修改后该用户已登录会话立即失效。系统至少保留一个启用的管理员。
- 审计日志：记录控制台写操作以及开放接口、MCP 的调用。可按对象类型筛选（意图、槽位、空间、知识库、文档、切片、工具、API Key、用户、导入）。接口：`GET /api/admin/users`、`POST /api/admin/users`、`PATCH /api/admin/users/{uid}`，`GET /api/admin/audit`。

## 9. 当前能力缺口（配置时不要绕开）

- **没有空间级运行参数。** 不能在平台上为某个空间保存默认店铺 ID。需要 `shop_id` 的工具，必须由使用方从会话注入，或向人要。若要做成平台配置，需要单独开发，不要在文档或配置里假装已经有这个字段。
- **西之月批量导入不在控制台。** 新增或更新官方目录后，要在服务器上跑 `python -m app.westmonth import`。
- **生产环境的 xclaw-cli 若未登录**，工具中心「测试调用」以及使用方的真实 CLI 调用都会失败。登录需要西之月账号（`xclaw-cli auth login` 或 `XCLAW_UMC_TOKEN`）。
- **平台没有开放的识别接口。** 控制台的单句测试只给运营自测，使用方必须在本地识别。
