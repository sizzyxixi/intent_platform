# 运营方配置手册

> 读者：**你**——在控制台配置业务空间、意图、知识库、工具和 API Key 的人，或持有写权限、要替运营写入意图 / 知识 / 注册工具的维护型 AI。
> 使用方（Bot / 业务系统）如何拉配置、识别、检索和调用工具，见同目录《使用方接入指南》。字段细节以 `openapi.yaml` 为准。
> 本文菜单名称、按钮文案与接口路径均按当前生产控制台与代码核对，控制台：`http://intent.47.86.15.93.sslip.io`。开放接口推荐基址：`http://47.86.15.93/intent-platform`（API `/intent-platform/api/v1`，MCP `/intent-platform/mcp`）。`*.sslip.io` 也可作备用 API 主机；若返回 500 且响应体为空，请改用 IP 路径。文档里的 `ipk_xxx` 只表示格式，不是能用的密钥。

## 零、先读：这个平台是什么

**平台是什么。** 这是一个按业务空间管理配置的中心。每个空间里有：意图分类、意图（例句、槽位、追问话术、置信与兜底规则）、知识库，以及已登记的工具，和「某个意图绑定了哪些工具、槽位如何映射成工具入参」。你在控制台维护这些配置，接入的 Bot 按版本拉取后使用。

**对你（运营方）的作用。** 你按业务配好空间、意图、槽位、知识、工具和绑定，再把只读 Key 交给使用方。平台负责把这些配置完整、按版本下发给 Bot。Bot 识别是否准确、工具能否调通、答复是否正确，取决于配置是否覆盖真实问法，以及使用方是否按《使用方接入指南》接入。

**边界（均按当前代码核对）：**

- 平台不替 Bot 跟终端用户对话，不保存用户的多轮会话，也不替 Bot 执行业务工具。
- 控制台「单句测试」和「测试调用」只供你自查配置，不代表线上 Bot 的识别或执行效果。开放接口没有识别接口，也没有给使用方的「代调用」接口。
- 使用方拿只读 Key 不能改你的配置。持有相应写权限的维护型 AI 可以写草稿意图、创建 / 更新 / 停用分类节点、启用或停用意图、注册 / 停用工具、把工具和知识绑到意图，以及新建知识库、导入知识和改切片。删除工具、删除分类、管理 Key，仍须登录控制台（分类与工具在开放接口只能停用）。

角色关系：

```
你（运营）  --配置 / 自查-->  本平台  --下发配置-->  使用方（Bot）  ←——对话——→  终端用户
                                              使用方（Bot）  --执行业务工具-->  业务系统
```

读完本节后，按下面的结论和清单开始配置。使用方怎么初始化和运行，不要写进本手册，让他们去读《使用方接入指南》。

## 结论

- 配置工作以**控制台登录会话**（`/api/admin`）为主。左侧菜单是「意图管理」「知识库」「工具中心」；管理员在左下角还有「用户与审计」。
- API Key（`/api/v1` 和 MCP）现在可以写分类节点、草稿意图、启用 / 停用意图、槽位、知识导入和切片、新建知识库、给意图关联知识，以及注册 / 更新 / 停用工具并把工具绑到意图。仍不能：调整分类层级、删除分类或工具、删除数据、管理 Key。细节见「API Key 能写什么」。
- 新空间按第 1 节清单走完，再把只读 Key 交给使用方。维护型 AI 的 Key 必须绑定它要写入的空间（例如要写 Moonclaw，Key 需要绑定 `mc`）。
- 西之月 xclaw-cli 工具的批量登记没有控制台按钮，要在服务器上跑命令。平台没有空间级运行参数，不能为某个空间预置默认的业务入参。

## API Key 能写什么、不能写什么

鉴权：`Authorization: Bearer ipk_xxx`。空间范围：绑定了空间的 Key，只能在这些空间上操作意图 / 槽位 / 运行时配置 / 意图绑工具；知识库与工具目录是全局的（注册的工具全平台可见）。权限字面量：`意图:读`、`意图:写`、`知识:读`、`知识:写`、`工具:读`、`工具:写`。分类节点、启用意图归 `意图:写`；新建知识库、关联知识还需要 `知识:写`（关联知识须两项都有）。

**API Key 可以（`/api/v1` 或同等 MCP）：**

| 能力 | 所需权限 | 接口或 MCP | 限制 |
|---|---|---|---|
| 读空间、运行时配置、意图、槽位、识别设置 | `意图:读` | `GET /spaces`、`/runtime-config`、`/intents`、`/intents/{code}`、`/slots`、`/recognition`；MCP `list_intents` / `get_intent` | 只读已绑定空间 |
| 读分类层级与分类树 | `意图:读` | `GET /taxonomy`；MCP `list_intents`（`view=taxonomy`） | 须指定已绑定空间 |
| 创建或更新分类节点 | `意图:写` | `POST /taxonomy/nodes`、`PUT /taxonomy/nodes/{code}`；MCP `taxonomy_upsert_node` | 按 `code` 幂等。`dry_run=true` 只校验。父节点用 `parent_code`，层级须符合该空间的分类层数 |
| 停用分类节点 | `意图:写` | `POST /taxonomy/nodes/{code}:disable`；MCP `taxonomy_disable_node` | **不能删除**。子树中有已启用意图时返回 409 `CATEGORY_IN_USE` |
| 启用 / 停用意图 | `意图:写` | `POST /intents/{code}:enable`、`POST /intents/{code}:disable`；MCP `intent_enable` / `intent_disable` | 启用须通过校验。PATCH 仍不能把意图设为启用 |
| 批量写入意图 | `意图:写` | `POST /intents:batchUpsert`（`mode=merge`）；MCP `upsert_intents` | **写入状态一律是「草稿」**，不会自动启用，也不改工具绑定、知识关联、启用状态 |
| 修改单条意图的有限字段 | `意图:写` | `PATCH /intents/{code}` | 只能改 `name`、`description`、`priority`、`examples`、`negative_examples`、`slot_bindings` |
| 增改删槽位 | `意图:写` | `POST /slots`、`PUT /slots/{name}`、`DELETE /slots/{name}` | 被意图使用的槽位不能删，返回 409 `SLOT_IN_USE` |
| 改识别阈值 | `意图:写` | `PUT /recognition` | 直接改线上配置版本，**慎用** |
| 列知识库、读文档和切片、检索 | `知识:读` | `GET /kbs`、`/kbs/{id}/documents`、`/kbs/{id}/chunks`、`POST /kbs/{id}/search`、`GET /imports/{id}`；MCP `search_knowledge` | REST 没有跨库检索，跨库用 MCP；没有单独的 `GET /kbs/{id}` |
| 新建知识库 | `知识:写` | `POST /kbs`、`GET /kbs/{id}`、`PATCH /kbs/{id}`；MCP `create_knowledge_base` | 不能删除知识库或文档 |
| 给意图关联 / 解绑知识 | `意图:写` **且** `知识:写` | `POST /intents/{code}/knowledge`、`DELETE /intents/{code}/knowledge`；MCP `intent_bind_knowledge` / `intent_unbind_knowledge` | `chunk_id` 为 `*` 表示整篇。须指定已绑定空间 |
| 导入知识、改切片 | `知识:写` | `POST /kbs/{id}/documents:import`（multipart）、`PUT /kbs/{id}/chunks/{chunk_id}`；MCP `import_knowledge` | **不能新建知识库**，目标库必须已存在。写接口需带 `Idempotency-Key` |
| 列工具、读单条、下载技能包 | `工具:读` | `GET /tools`（可 `source=external` / `builtin`）、`GET /tools/{name}`、`GET /tools/{name}/skill-package`；MCP `list_tools` | 工具全平台通用，不需要 `X-Space-Id` |
| 注册或更新工具 | `工具:写` | `POST /tools`（按 `name` 幂等，不存在 201、已存在 200）、`PUT /tools/{name}`；MCP `register_tool` / `update_tool` | 见第 5.1 节。`dry_run=true` 只校验不写入。不能单独创建 MCP 子工具（先登记服务再同步）。不能改内置工具。HTTP 的 `secret` 不会出现在响应里。写入须带 `Idempotency-Key`（dry_run 除外） |
| 停用工具 | `工具:写` | `POST /tools/{name}:disable`；MCP `disable_tool` | **不能删除**工具，只能停用。停用后不再进入运行时配置，也不能新绑定；已绑定的已启用意图可能被降为草稿 |
| 登记 MCP 服务并同步、上传技能包 | `工具:写` | `POST /mcp-servers`、`PUT /mcp-servers/{name}`、`POST /mcp-servers/{name}/sync/preview`、`…/sync/apply`、`POST /skill-packages` | 技能包先暂存拿到 `package_id`，再 `POST /tools` 且 `type=skill` |
| 绑定 / 解绑意图上的工具 | `意图:写` **且** `工具:写` | `POST /intents/{code}/tools`、`DELETE /intents/{code}/tools/{tool}`；MCP `intent_bind_tool` / `intent_unbind_tool` | 必须带 Key 已绑定的空间。已绑定则更新 `param_map`。已启用意图也可以绑，成功后空间版本 +1。`dry_run=true` 只校验 |

**API Key 做不到（必须登录控制台，走 `/api/admin` 会话）：**

- 新建 / 修改业务空间
- 调整分类层级、新增或改分类节点
- 把意图归档（启用和停用已对持有 `意图:写` 的 Key 开放：`POST /intents/{code}:enable` / `:disable`）
- 删除意图（槽位可以用带 `意图:写` 的 Key 删除，但被意图占用时会失败）
- 删除知识库、删除文档（新建知识库已对 `知识:写` 开放：`POST /kbs`）
- **删除**工具（开放接口只能停用）
- 测试调用（真实执行）
- 创建、吊销 API Key
- 用户管理、审计日志查询

不要把管理后台接口当成开放接口去调。`POST /api/admin/spaces/{id}/test` 是控制台的单句识别测试，不接受 API Key。

## 1. 新业务空间初始化清单

下面按控制台真实路径列出。全部做完再把只读 Key 交给使用方。

1. **新建空间**（管理员）：意图管理顶栏「＋ 新建空间」，填写：空间 ID（小写英文，创建后不可改）、意图编码前缀（1～4 位大写字母）、名称、描述、对应 Bot / 智能体。新空间的意图、分类、槽位、导入记录、运行时配置和版本都独立；知识库和工具全平台通用。新空间默认层级为「大类 / 问题桶 / 意图」，并带一个「通用 / 默认」分类。接口：`POST /api/admin/spaces`。
2. **按业务调整分类层级**：意图管理 › 空间设置 ›「分类层级」（最多 5 层分类 + 最末层意图）。插入或删除会弹出「影响预览」，确认后配置版本 +1。再在「分类」里新增、改名。接口：`POST /api/admin/spaces/{sid}/levels/preview`、`PUT …/levels`、`POST/PATCH/DELETE …/categories`。
3. **维护槽位**：意图管理 › 槽位。先定义本空间要用的槽位（名称、类型、是否必填、追问话术）。不向用户追问的槽位，把 `ask` 写成「（不向买家追问：…）」这类说明。
4. **登记或确认工具**：工具中心 › 工具目录。平台已登记内置工具和西之月快照中的命令 / 技能。新的 HTTP / CLI / MCP / 工作流 / 技能按第 5 节注册。写操作打开「需确认」。
5. **写意图**：意图管理 › 意图列表 ›「＋ 新建意图」，或用带 `意图:写` 的 Key 走 `POST /api/v1/intents:batchUpsert`（结果是草稿）。填写描述、标准例句、反例、槽位绑定。
6. **绑定工具和知识**：在意图详情里关联工具（先搜索再选择，不要一次加载全部工具）并填写 `param_map`；或用同时持有 `意图:写` 与 `工具:写` 的 Key 调用 `POST /api/v1/intents/{code}/tools`（见第 5.1 节）。关联知识库 / 文档 / 切片（区分「参考」和「校验」）可在控制台做，或用同时持有 `意图:写` 与 `知识:写` 的 Key 调用 `POST /api/v1/intents/{code}/knowledge`。
7. **导入或撰写知识**：知识库 › 导入文档；或先「＋ 新建知识库」。导入后在知识库详情校对切片，用「知识库检索」试查。把校验类切片关联到意图。
8. **启用前验证**：意图详情「验证」，以及空间内的单句测试。通过后再把意图改为「启用」（配置版本 +1，使用方下次拉取才会看到）。也可用 `POST /api/v1/intents/{code}:enable`。
9. **发 Key**：工具中心 › 接入与密钥 ›「＋ 新建 Key」。使用方一般只需只读三项，并绑定本空间。完整 Key 只显示一次，写入对方约定位置（环境变量 `INTENT_PLATFORM_API_KEY` 或 `~/.intent-platform/config.json`，权限 600）。需要 AI 代写草稿意图或导入知识时，另建一把带 `意图:写` / `知识:写` 的 Key；需要 AI 注册工具或把工具绑到意图时，再勾选 `工具:写`（绑工具必须同时有 `意图:写`），并绑定对应空间。
10. **把《使用方接入指南》交给使用方**，说明空间 ID、该空间工具需要哪些运行环境（例如是否要登录某 CLI），以及会话里需要注入哪些业务入参。
11. **抽查线上**：用使用方的只读 Key 调 `GET /api/v1/spaces` 和 `GET /api/v1/runtime-config`，确认已启用意图和绑定工具出现在配置里。

## 2. 空间、分类与识别设置

空间设置页除分类外，还可改识别阈值、候选下限、最多候选数、澄清次数、槽位追问次数、工具重试次数、最终动作（转人工 / 通用助手 / 拒绝）及拒绝文案。改这些会提升配置版本。

控制台：`GET/PUT /api/admin/spaces/{sid}/recognition`。API Key 也可用 `GET/PUT /api/v1/recognition`（写需要 `意图:写`），因为直接影响线上，改之前要确认业务已同意。

运行时配置预览：控制台 `GET /api/admin/spaces/{sid}/runtime-config`（会话）；使用方用 `GET /api/v1/runtime-config`。

## 3. 意图与槽位

- 意图编码由空间前缀 + 分类路径生成，创建后不要随意改。
- 状态：草稿 → 启用 → 停用 / 归档。只有「启用」会进入运行时配置。状态变更：控制台 `POST /api/admin/intents/{code}/status`。
- 例句要覆盖用户的真实说法；反例用来避免误识别。
- 槽位绑定决定识别后要收集哪些信息，以及工具 `param_map` 从哪取值。
- 验证：`POST /api/admin/intents/{code}/validate`；单句测试：`POST /api/admin/spaces/{sid}/test`（会话，不是 API Key）。
- 批量导入：意图管理 › 导入记录，先预览再应用。`POST /api/admin/spaces/{sid}/imports/preview`、`…/imports/apply`。
- 用 API Key 写入意图时用 `mode=merge`，只创建或更新为草稿；不要假定它已经启用。绑工具请用第 5.1 节的绑定接口，不要指望 `batchUpsert` 会写绑定。

## 4. 知识库

知识库全平台通用。页标题是「AI知识库」。

- 新建知识库、改元数据、看删除影响、删除库或文档：仅控制台（`POST /api/admin/kbs` 等）。API Key **不能**创建知识库。
- 导入：控制台「导入文档」，或 API Key `POST /api/v1/kbs/{kb_id}/documents:import`（`知识:写`）。导入是异步的，用返回的任务 ID 查进度。
- 切片：导入后务必人工校对。控制台与 API Key 都是 `PUT …/kbs/{kb_id}/chunks/{chunk_id}`（API Key 路径为 `/api/v1`）。
- 检索试查：知识库 › 知识库检索，或 `POST /api/v1/kbs/{kb_id}/search`。
- 把切片或整篇关联到意图，只能在意图详情里做。校验类知识会出现在运行时配置的 `validation_sets`。

当前 cs 空间已关联的规则类知识库包括回复规则、置信与澄清、询价规则等（以控制台为准）。删除知识库前先看「影响」，避免把已启用意图的校验知识拆掉。

## 5. 工具中心

工具目录默认每页 20 条，可改为 50 / 100；搜索和筛选在服务端执行（当前登记量约七千条，主要是西之月 CLI）。给意图绑工具时也是先搜索再选。

- **注册工具**：工具目录「＋ 注册工具」。类型包括 CLI、HTTP、MCP、工作流、技能。写操作打开「需确认」（`confirm_required`）。保存后可再编辑。接口：`POST/PUT/PATCH/DELETE /api/admin/tools`。
- **MCP 服务**：在工具目录「＋ 注册工具」中选择类型 MCP，登记服务本身；保存后同步 `tools/list`（预览再应用）。意图只关联其中的具体工具，不能整体关联一个服务。接口：`GET/POST /api/admin/mcp-servers`，`POST /api/admin/mcp-servers/{name}/sync/preview` 与 `…/sync/apply`。
- **技能包**：上传 zip，平台按包内 SKILL.md 登记。`POST /api/admin/skill-packages`。
- **西之月 xclaw-cli 批量导入**：控制台**没有**「从西之月导入」按钮。在部署环境执行 `python -m app.westmonth import`（快照在 `backend/seed/westmonth/`）。查看状态用 `python -m app.westmonth status`。官方目录见 https://open.westmonth.com/cli 。
- **测试调用**：工具详情「测试调用」。管理员可真实执行；写工具必须勾选确认。CLI 工具依赖运行环境已安装并登录对应 CLI（生产服务器上的 `xclaw-cli` 若尚未 `auth login`，测试调用会失败，这是环境问题，不是工具登记错误）。接口：`POST /api/admin/tools/{name}/test`。

平台只登记调用方式，不代使用方在线上执行，也不下发第三方密钥。

## 5.1 用 API Key 让 AI 注册工具

控制台仍可注册工具。同时，持有 `工具:写` 的维护型 AI 也可以通过开放接口完成同等写入。工具一旦注册就是**全平台可见**的，不按空间隔离；Key 是否绑定某空间，不影响注册本身，只约束「把工具绑到哪个空间的意图」。

### 权限与入口

- 创建 Key 时在「接入与密钥」勾选 `工具:写`。只读的 `工具:读` 只能列表和读取，不能写入。
- REST 前缀（推荐）：`http://47.86.15.93/intent-platform/api/v1`。控制台同域备用：`http://intent.47.86.15.93.sslip.io/api/v1`。请求头 `Authorization: Bearer ipk_xxx`，写入还必须带 `Idempotency-Key`（最长 64 字符）。`dry_run=true` 时不写库，也不需要幂等键。
- 同等 MCP 工具（推荐 `POST http://47.86.15.93/intent-platform/mcp`）：`register_tool`、`update_tool`、`disable_tool`；绑定用 `intent_bind_tool`、`intent_unbind_tool`（后两个还需要 `意图:写`，参数里要带 `space` 或请求头 `X-Space-Id`）。MCP 写入把幂等键放在参数 `idempotency_key` 里。

### 注册与更新（按 name 幂等）

`name` 是稳定编码：小写字母开头，只含小写字母 / 数字 / 下划线，最长 120。同一 `name` 再提交是更新，不会建出第二条。

先做 dry-run，通过后再正式写入：

```http
POST /api/v1/tools
Authorization: Bearer ipk_xxx
Idempotency-Key: tool-inventory-lookup-1
Content-Type: application/json
```

HTTP 工具示例：

```json
{
  "name": "inventory_lookup",
  "type": "http",
  "display_name": "库存查询",
  "description": "按商品编码查询当前可售库存。",
  "owner": "运营",
  "params": [
    {"name": "sku", "type": "string", "required": true, "description": "商品编码"}
  ],
  "config": {"url": "https://example.com/inventory", "method": "GET", "auth": "无"},
  "dry_run": true
}
```

校验通过后去掉 `dry_run`（或设为 false）再提交。不存在则 201 且 `action=created`，已存在则 200 且 `action=updated`。也可用 `PUT /api/v1/tools/{name}` 做更新（路径里的 name 不能改）。

CLI 工具把 `type` 换成 `cli`，`config` 使用例如：

```json
{
  "bin": "mycli",
  "command_template": "mycli order get {order_id}",
  "auth": "无",
  "output_format": "json",
  "confirm_required": false,
  "output_description": "订单状态 JSON"
}
```

登记 MCP 服务（不是子工具）：`POST /api/v1/mcp-servers`，然后 `POST /api/v1/mcp-servers/{name}/sync/preview` 预览，确认后 `…/sync/apply`。不要用 `POST /tools` 且 `type=mcp` 去单独建一条子工具，接口会返回 422。

写操作类工具把 `config.confirm_required` 设为 true，使用方调用前必须向用户确认。这一规则与控制台登记时相同。

### 常见校验错误

| HTTP | code | 典型原因 | 处理 |
|---|---|---|---|
| 403 | `SCOPE_FORBIDDEN` | Key 没有 `工具:写`，或绑工具时缺少 `意图:写` | 停下来，请管理员改 Key 权限，不要改用控制台账号冒充开放接口 |
| 403 | `SPACE_FORBIDDEN` | 绑工具时空间不在 Key 绑定范围 | 换空间或换 Key |
| 403 | `BUILTIN_READONLY` | 试图修改或停用平台内置工具 | 不要动内置工具 |
| 404 | `TOOL_NOT_FOUND` / `INTENT_NOT_FOUND` | 名称或编码不存在，或意图不在该空间 | 用 `GET /tools/{name}`、`GET /intents/{code}` 确认 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同一个 `Idempotency-Key` 被用于不同请求体 | 换一个新的键 |
| 409 | `TOOL_EXISTS` | 仅在不允许更新的创建路径上出现；开放接口的 `POST /tools` 是 upsert，一般不会返回这个码 | — |
| 422 | （校验失败） | URL 不合法、`name` 格式不对、缺少必填字段、试图单独注册 MCP 子工具、入参或命令模板不完整 | 按 `details.problems` 修正后重试；可先 `dry_run` |

响应里不会返回 HTTP 密钥。同键同请求体会直接重放首次结果，响应头带 `Idempotent-Replayed: true`。

### 绑定到意图（param_map）

需要同时持有 `意图:写` 和 `工具:写`，并指定空间：

```http
POST /api/v1/intents/B.EXAMPLE.CODE/tools
Authorization: Bearer ipk_xxx
X-Space-Id: {space_id}
Idempotency-Key: bind-1
Content-Type: application/json

{
  "tool": "inventory_lookup",
  "param_map": {
    "sku": {"source": "槽位", "value": "sku"}
  },
  "dry_run": true
}
```

`param_map` 的键是工具入参名；`source` 只能是 `槽位`、`常量` 或 `上下文`。已绑定同一工具时，这次提交会替换映射。解绑：`DELETE /api/v1/intents/{code}/tools/{tool}`。未绑定则原样返回，不算失败。

绑定前建议 dry-run。不要把尚未验收的探针工具绑到已启用的真实意图上。

### 停用与核验

- 停用：`POST /api/v1/tools/{name}:disable`。开放接口没有删除接口。
- 核验步骤：1）`dry_run` 通过；2）正式 `POST /tools`，用 `GET /tools/{name}` 看到 `enabled=true` 且字段正确；3）如需给草稿意图试绑定，走 dry-run 再绑定，确认 `param_map`；4）验收结束若只是探针工具，立即停用，不要留在已启用意图上；5）需要时在控制台「用户与审计」按对象类型「工具」查看审计，操作者类型为 `api_key`。

## 5.2 用 API Key 写分类、启用意图、建知识库

写入前先 `GET /api/v1/taxonomy` 看该空间有几层分类。Moonclaw 是「大类 / 问题桶」，路径要两段；1688 智能客服目前是「阶段」一层。

创建或更新节点（按 `code` 幂等，先 dry-run）：

```http
POST /api/v1/taxonomy/nodes
Authorization: Bearer ipk_xxx
X-Space-Id: {space_id}
Idempotency-Key: tax-order-1
Content-Type: application/json

{"code": "ORDER", "name": "订单", "depth": 1, "dry_run": true}
```

分类不存在时，`batchUpsert` 会返回 `UNKNOWN_CATEGORY`，并提示先调用本接口或使用 `auto_create_parents=true`（路径每段须为编码，或 `{code, name}`）。也可一次提交节点和意图：`POST /api/v1/batchUpsert`（失败则全部回滚，错误在 `details.items`）。

启用意图：`POST /api/v1/intents/{code}:enable`（须通过启用前校验）。停用分类前先停用或移走该子树下的已启用意图，否则 409。

新建知识库：`POST /api/v1/kbs`，`{"name": "…", "type": "表格知识库"}`。导入文档仍用已有的 `documents:import`。

## 6. 把工具和知识绑到意图


在意图详情中完成：

- 关联工具，为每个入参指定 `param_map`：来源为槽位 / 常量 / 上下文。必填入参必须能取到值，否则使用方按规则不会调用。
- 关联知识，标记参考或校验；校验可指定整篇（`chunk_id="*"`）。
- 改绑定会提升配置版本。用 API Key 绑 / 解绑工具见第 5.1 节；关联知识用 `POST /api/v1/intents/{code}/knowledge`（`意图:写` + `知识:写`）。

## 7. API Key 管理

仅管理员。路径：工具中心 › 接入与密钥 ›「＋ 新建 Key」（弹窗标题「新建 API Key」）。

- 填写名称、绑定空间、权限。绑定空间只约束意图 / 槽位 / 运行时配置；知识与工具仍是全局可读（在具备对应读权限时）。
- 完整 Key 只显示一次，前缀 `ipk_`。之后列表只显示提示（如 `ipk_ak_xxxx_••••••••`）。
- 吊销：列表中操作，之后该 Key 返回 401 `KEY_REVOKED`。接口：`GET/POST /api/admin/api-keys`，`POST /api/admin/api-keys/{kid}/revoke`。
- 给使用方：只读三项 + 绑定其业务空间，并告知《使用方接入指南》第 1 节的存放约定。
- 给维护型 AI：按需加 `意图:写` / `知识:写` / `工具:写`。说明第 0 节的能力边界：可以写分类和草稿意图、启用意图、注册或停用工具、关联知识、新建知识库；仍不能删除工具或分类、不能管理 Key。Key 必须绑定要写入的空间。

本页同时提供文档下载：使用方接入指南、运营方配置手册，以及索引《AI使用说明》、OpenAPI。

## 8. 用户与审计

左下角「用户与审计」（仅管理员）。

- 用户：新建控制台账号，角色为管理员 / 编辑 / 只读；可改角色、停用、重置密码。修改后该用户已登录会话立即失效。系统至少保留一个启用的管理员。
- 审计日志：记录控制台写操作以及开放接口、MCP 的调用。可按对象类型筛选（意图、槽位、空间、知识库、文档、切片、工具、API Key、用户、导入）。接口：`GET /api/admin/users`、`POST /api/admin/users`、`PATCH /api/admin/users/{uid}`，`GET /api/admin/audit`。

## 9. 当前能力缺口（配置时不要绕开）

- **没有空间级运行参数。** 不能在平台上为某个空间预置默认的业务入参。工具定义里要求从会话注入的入参（例如某个空间的店铺标识），由使用方从自己的上下文提供。若要做成平台配置，需要单独开发，不要假装已经有这个字段。
- **西之月批量导入不在控制台。** 新增或更新官方目录后，要在服务器上跑 `python -m app.westmonth import`。
- **生产环境的 xclaw-cli 若未登录**，工具中心「测试调用」以及使用方的真实 CLI 调用都会失败。登录需要西之月账号（`xclaw-cli auth login` 或 `XCLAW_UMC_TOKEN`）。
- **平台没有开放的识别接口。** 控制台的单句测试只给运营自测，使用方必须在本地识别。
- **工具结果没有通用的输出字段映射。** 除工作流的 `output_mapping` 外，平台不会告诉 Bot 该从返回值里取哪个字段来组织回复，需要写在知识或工具说明里。
