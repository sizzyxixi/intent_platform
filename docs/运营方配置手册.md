# 运营方配置手册

> 读者：**你**——在控制台配置业务空间、意图、知识库、工具和 API Key 的人，或持有写权限、要替运营写入配置的维护型 AI。
> 使用方（Bot / 业务系统）如何拉配置、识别和调用工具，见同目录《使用方接入指南》。字段细节以 `openapi.yaml` 为准。
> 控制台：`http://intent.47.86.15.93.sslip.io`。开放接口推荐基址：`http://47.86.15.93/intent-platform`（API `/intent-platform/api/v1`，MCP `/intent-platform/mcp`）。`*.sslip.io` 也可作备用 API 主机；若返回 500 且响应体为空，请改用 IP 路径。文中的 `ipk_xxx` 只表示格式，不是能用的密钥。

## 零、先读：这个平台是什么

**平台是什么。** 这是一个按业务空间集中管理「意图、知识、工具」的配置中心。每个空间有自己的分类树、意图（描述、例句、槽位、处理方式）和识别 / 兜底设置。知识库和工具全平台共用，意图按需要引用它们。你在控制台维护这些配置，接入的 Bot 按版本拉取后使用。

**对你（运营方）的作用。** 你按业务配好空间、意图、槽位、知识、工具和绑定，再把只读 Key 交给使用方。平台负责把这些配置完整、按版本下发给 Bot。Bot 识别是否准确、工具能否调通、答复是否正确，取决于配置是否覆盖真实问法，以及使用方是否按《使用方接入指南》接入。

**边界（按当前实现核对）：**

- 平台不替 Bot 跟终端用户对话，不保存用户的多轮会话，也不替 Bot 执行业务工具。
- 控制台「单句测试」和「测试调用」只供你自查配置，不代表线上效果。开放接口没有识别接口，也没有给使用方的「代调用」接口。
- 平台没有空间级运行时业务参数，不能为某个空间预置店铺 ID 这类默认值。
- 使用方拿只读 Key 不能改你的配置。持有相应写权限的维护型 AI 可以写草稿意图、创建 / 更新 / 停用分类节点、启用或停用意图、注册 / 停用工具、把工具和知识绑到意图，以及新建知识库、导入知识和改切片。删除工具、删除分类、调整分类层级、管理 Key，仍须登录控制台（分类与工具在开放接口只能停用）。

角色关系：

```
你（运营）  --配置 / 自查-->  本平台  --下发配置-->  使用方（Bot）  ←——对话——→  终端用户
                                              使用方（Bot）  --执行业务工具-->  业务系统
```

请把《使用方接入指南》一并交给使用方，尤其是其中「对终端用户怎么说」：客服对用户不能提「知识库」「检索」「补进知识库」这类内部说法，查不到时按兜底处理，不能请用户补资料。

## 1. API Key：创建、权限、吊销与删除

仅管理员。路径：工具中心 › 接入与密钥 ›「＋ 新建 Key」（弹窗标题「新建 API Key」）。接口：`GET/POST /api/admin/api-keys`，`POST /api/admin/api-keys/{kid}/revoke`，`DELETE /api/admin/api-keys/{kid}`。

1. 填写名称。
2. 绑定至少一个空间。绑定范围只约束意图类接口（意图、槽位、分类、空间设置、运行时配置、把工具绑到该空间的意图）；知识库与工具目录是全局的，仍受下面的权限控制。
3. 勾选权限，至少一项。字面量：`意图:读`、`意图:写`、`知识:读`、`知识:写`、`工具:读`、`工具:写`。
4. 创建后完整 Key 只显示一次，前缀 `ipk_`。之后列表只显示提示。把 Key 交给使用方时，告知写入环境变量 `INTENT_PLATFORM_API_KEY` 或文件 `~/.intent-platform/config.json`（权限 600），不要在其他目录搜索。

建议的权限组合：

- 使用方 Bot：只读三项（`意图:读`、`知识:读`、`工具:读`），并绑定其业务空间。同时把《使用方接入指南》交给对方。
- 维护型 AI：按需加写权限。写草稿意图、分类节点、启用 / 停用意图、槽位、把已有工具绑到意图，需要 `意图:写`。新建知识库、导入知识、给意图关联知识，还需要 `知识:写`（关联知识须两项都有）。只有要注册 / 更新 / 停用工具时，才勾选 `工具:写`。Key 必须绑定要写入的空间。

**吊销与删除：** 列表中先「吊销」，之后该 Key 返回 401 `KEY_REVOKED`。吊销后出现「删除」，确认后彻底去掉这一行，不留表记录（审计日志保留）。有效 Key 必须先吊销才能删除。

本页同时提供文档下载：使用方接入指南、运营方配置手册，以及索引《AI使用说明》、OpenAPI。

### 1.1 API Key 能写什么、不能写什么

鉴权：`Authorization: Bearer ipk_xxx`。写请求须带 `Idempotency-Key`（≤ 64 字符；`dry_run=true` 除外）。意图类请求带 `X-Space-Id` 或 `?space=`。

**可以（`/api/v1` 或同等 MCP）：**

| 能力 | 所需权限 | 接口或 MCP | 限制 |
|---|---|---|---|
| 读空间、运行时配置、意图、槽位、识别设置 | `意图:读` | `GET /spaces`、`/runtime-config`、`/intents`、`/intents/{code}`、`/slots`、`/recognition`；MCP `list_intents` / `get_intent` | 只读已绑定空间 |
| 读分类树 | `意图:读` | `GET /taxonomy`；MCP `list_intents`（`view=taxonomy`） | 可选 `max_depth`、`parent`；节点含 `has_children`、`child_count` |
| 创建或更新分类节点 | `意图:写` | `POST /taxonomy/nodes`、`PUT /taxonomy/nodes/{code}`；MCP `taxonomy_upsert_node` | 按 `code` 幂等；`dry_run` 只校验。不能调整「有几层、每层叫什么」 |
| 停用分类节点 | `意图:写` | `POST /taxonomy/nodes/{code}:disable`；MCP `taxonomy_disable_node` | **不能删除**。子树中有已启用意图时 409 `CATEGORY_IN_USE` |
| 启用 / 停用意图 | `意图:写` | `POST /intents/{code}:enable`、`:disable`；MCP `intent_enable` / `intent_disable` | 启用须通过校验。PATCH 不能把意图直接设为启用。另见第 9 节已知问题 |
| 批量写入意图 | `意图:写` | `POST /intents:batchUpsert`（`mode=merge`）；MCP `upsert_intents` | 结果一律是草稿，不改工具绑定、知识关联、启用状态 |
| 修改单条意图的有限字段 | `意图:写` | `PATCH /intents/{code}` | 只能改草稿 / 停用意图的 `name`、`description`、`examples`、`slots`、`status`（不能直接启用）、`handling` |
| 增改删槽位 | `意图:写` | `POST /slots`、`PUT /slots/{name}`、`DELETE /slots/{name}` | 被使用时删除 409 `SLOT_IN_USE` |
| 改识别与空间兜底 | `意图:写` | `PUT /recognition` | 推荐传 `fallback`。仍兼容旧的 `final_action`。会提升配置版本，**慎用** |
| 列、读、检索知识 | `知识:读` | `GET /kbs`、`GET /kbs/{id}`、`/kbs/{id}/documents`、`/kbs/{id}/chunks`、`POST /kbs/{id}/search`、`GET /imports/{id}`；MCP `search_knowledge` | REST 没有跨库检索，跨库用 MCP |
| 新建知识库、改名称 / 描述 | `知识:写` | `POST /kbs`、`PATCH /kbs/{id}`；MCP `create_knowledge_base` | 不能删除知识库或文档 |
| 给意图关联 / 解绑知识 | `意图:写` **且** `知识:写` | `POST / DELETE /intents/{code}/knowledge`；MCP `intent_bind_knowledge` / `intent_unbind_knowledge` | `chunk_id` 为 `*` 表示整篇。非 `tool_flow` 的意图不能关联 |
| 导入知识、改切片 | `知识:写` | `POST /kbs/{id}/documents:import`、`PUT /kbs/{id}/chunks/{chunk_id}`；MCP `import_knowledge` | 目标库必须已存在 |
| 列工具、读单条、下载技能包 | `工具:读` | `GET /tools`、`GET /tools/{name}`、`GET /tools/{name}/skill-package`；MCP `list_tools` | 开放接口的工具列表**目前没有分页**，数量大时不要一次拉全量；控制台已分页 |
| 注册或更新工具 | `工具:写` | `POST /tools`（按 `name` 幂等）、`PUT /tools/{name}`；MCP `register_tool` / `update_tool` | 不能单独创建 MCP 子工具；不能改内置工具。`dry_run` 只校验 |
| 停用工具 | `工具:写` | `POST /tools/{name}:disable`；MCP `disable_tool` | **不能删除**。已绑定的已启用意图可能被降为草稿 |
| 登记 MCP 服务并同步、上传技能包 | `工具:写` | `POST /mcp-servers`、`PUT /mcp-servers/{name}`、`…/sync/preview`、`…/sync/apply`、`POST /skill-packages` | 技能包先暂存拿到 `package_id`，再注册 `type=skill` 的工具 |
| 绑定 / 解绑意图上的工具 | `意图:写` | `POST /intents/{code}/tools`、`DELETE /intents/{code}/tools/{tool}`；MCP `intent_bind_tool` / `intent_unbind_tool` | **不需要** `工具:写`。须指定已绑定空间。非 `tool_flow` 不能绑定 |

**做不到（必须登录控制台）：** 新建或修改业务空间；调整分类层级（插入 / 删除层、改层名）；删除分类、工具、知识库或文档；工具真实测试调用；创建、吊销、删除 API Key；用户管理与审计查询。

## 2. 新业务空间初始化清单

全部做完再把只读 Key 交给使用方。

1. **新建空间**（管理员）：意图管理顶栏「＋ 新建空间」。填写空间 ID*（2～32 位小写字母 / 数字 / 下划线，字母开头，创建后不可改）、意图编码前缀*（1～4 位大写字母，全平台唯一）、名称*、描述、对应 Bot / 智能体*。新空间的意图、分类、槽位、导入记录和运行时版本都独立；知识库和工具全平台通用。默认层级为「大类 → 问题桶 → 意图」，并带「通用（GEN）/ 默认」。接口：`POST /api/admin/spaces`。
2. **按业务调整分类层级**：意图管理 › 空间设置 ›「分类层级」（0～5 层分类 + 最末层意图）。插入或删除会先出「影响预览」，确认后配置版本 +1。再在「分类」里新增、改名。不要套用其他空间的层名。
3. **维护槽位**：意图管理 › 槽位。定义本空间要用的槽位（英文名、显示名、类型、枚举可选值、默认追问话术）。是否必填是在意图上勾选的。不向用户追问的槽位，把追问话术写成「（不向用户追问：…）」这类说明。
4. **登记或确认工具**：工具中心 › 工具目录。已有的全平台工具可以直接复用。新的 HTTP / CLI / MCP / 工作流 / 技能按第 6 节注册。写操作打开「需确认」。
5. **写意图**：意图列表 ›「＋ 新建意图」，或用带 `意图:写` 的 Key 走 `POST /api/v1/intents:batchUpsert`（结果是草稿）。填写描述（至少 15 个字，写清什么算、什么不算）、至少 3 条例句、槽位，并选择**处理方式**（见第 4 节）。
6. **绑定工具和知识**：仅处理方式为「工具与知识流程」时才需要。关联工具用可搜索的下拉框并填写 `param_map`；关联知识时区分「参考」和「校验」。已是转人工 / 固定话术 / 自由发挥的意图，接口会拒绝绑定。
7. **导入或撰写知识**：知识库 ›「＋ 新建」或「导入文档」。导入后校对切片，用「知识库检索」试查，再把需要的切片关联到意图。
8. **启用前验证**：意图详情的校验，以及空间内的单句测试。通过后再改为「启用」（配置版本 +1）。也可用 `POST /api/v1/intents/{code}:enable`。请先阅读第 9 节：非工具流程的意图目前还启用不了。
9. **发 Key**：按第 1 节创建，把《使用方接入指南》和空间 ID、该空间工具需要的运行环境，以及会话里需要注入的业务入参，一并告诉使用方。
10. **抽查**：用使用方的只读 Key 调 `GET /api/v1/spaces` 和 `GET /api/v1/runtime-config`，确认已启用意图出现在配置里。

## 3. 空间、分类、识别与兜底

空间设置页（意图管理 › 空间设置）可改：

- 识别阈值（0～1，默认 0.6）。候选下限 = 阈值 ÷ 2，只读。
- 澄清话术、澄清最多次数（0～5，默认 2）、每个必填槽位的追问最多次数（默认 2）、工具失败重试次数（0～3，默认 1）。
- **空间兜底**：用户一句话都匹配不上，或澄清 / 追问 / 工具失败超限时怎么处理。选项与意图处理方式同一套，但没有「工具与知识流程」：转人工（可选说明）、固定话术（至少一条，并选「按意思表达」或「完全固定」）、让 AI 自由发挥（可选发挥说明）。

保存有改动才会让配置版本 +1。控制台：`GET/PUT /api/admin/spaces/{sid}/recognition`。API Key 也可用 `GET/PUT /api/v1/recognition`（写需要 `意图:写`），因为直接影响线上，改之前要确认。推荐传 `fallback`；`final_action` 是兼容字段。使用方应以 `fallback` 为准。

分类层级在同一页维护。改层名、插入或删除层必须先预览。分类节点可新增下级、改名、删除（有下级或有意图时不能删）；只有第一层可以设编码。开放接口可按 code 创建 / 更新 / 停用节点，不能删除，也不能改层数。

**已知问题：** 新建空间时，兜底方式的默认值目前按空间 ID 写死——只有 ID 为 `cs` 的空间默认「转人工」，其他空间（包括之后新建的）默认「让 AI 自由发挥」。这不是可配置的通用规则。建好空间后，请在空间设置里按该业务的实际需要改一次并保存。

## 4. 意图与处理方式

意图编码由空间前缀和第一层分类编码组成（第一层没有编码时为 `{前缀}.{意图}`），创建后不可改。状态：草稿、启用、停用。只有「启用」会进入运行时配置。

处理方式 `handling` 在意图编辑抽屉里选择，缺省为「工具与知识流程」：

| 选项 | mode | 说明 |
|---|---|---|
| 工具与知识流程 | `tool_flow` | 默认。可以绑工具和知识，使用方会追问槽位、查知识、调工具 |
| 转人工 | `handoff_human` | 可选填写转出说明。不能绑工具或知识 |
| 固定话术 | `fixed_reply` | 至少写一条话术（最多 10 条）。并选择「按意思表达」（默认，使用方可改写但须保原意）或「完全固定」（必须原样输出） |
| 让 AI 自由发挥 | `llm_free` | 可选填写发挥说明。不能绑工具或知识 |

若意图已有工具或知识绑定，要改成后三种必须先解绑。批量写入时可在每条意图上带 `handling`。

启用前校验（控制台保存为启用，或 `POST /intents/{code}:enable`）：名称与编码合格、描述不少于 15 个字、例句不少于 3 条、挂在最末一层且分类未停用、槽位合法且必填槽位有追问；若为工具流程，关联的知识和工具必须有效，必填入参已映射。

**已知问题：** 启用校验里「至少关联 1 条知识或 1 个工具」尚未按处理方式分支。因此转人工、固定话术、自由发挥这三种意图虽然不能绑定，也会被这条规则拦住，**目前无法启用**，也就不会出现在运行时配置里。草稿和停用状态仍可保存这三种配置。修复前，未匹配用户的处理请先用**空间兜底**承担。

其他说明：

- 例句要覆盖用户的真实说法。
- 单句测试（`POST /api/admin/spaces/{sid}/test`）只供运营自查，不接受 API Key，也不能当作线上识别。
- 批量导入：意图管理 ›「导入意图」，先预览再应用。文件里若仍带旧的意图级「兜底」字段，会被忽略。
- 用 API Key 写入时用 `mode=merge`，只创建或更新为草稿；不要假定它已经启用。绑工具请用绑定接口，`batchUpsert` 不会写绑定。

## 5. 知识库

知识库全平台通用，不随空间切换。页标题是「AI知识库」。

- **新建：** 控制台「＋ 新建」，或 API Key `POST /api/v1/kbs`（`知识:写`）。填写名称*、类型*（表格知识库或图文知识库-富文本），以及可选的「描述」（自由文本，不超过 2000 字）。不要再填平台 / 站点 / 语言 / 类目等固化的适用范围字段；旧数据已迁移到描述里。
- **改名称或描述：** 控制台，或 `PATCH /api/v1/kbs/{id}`。删除库或文档只能在控制台做；删除前先看「影响」，避免把已启用意图的校验知识拆掉。
- **导入：** 控制台「导入文档」，或 `POST /api/v1/kbs/{kb_id}/documents:import`。导入是异步的，用返回的任务 ID 查进度。表格库表头必须完全一致；图文库的图片暂不做 OCR。
- **切片：** 导入后务必人工校对。`PUT /api/v1/kbs/{kb_id}/chunks/{chunk_id}`。切片仍可带 platform / site / language / category 标签，供检索过滤。
- **试查：** 知识库 › 知识库检索，或 `POST /api/v1/kbs/{kb_id}/search`。跨库检索用 MCP `search_knowledge`。
- 把切片或整篇关联到意图，在意图编辑里做（仅工具与知识流程），或用同时持有 `意图:写` 与 `知识:写` 的 Key 调用 `POST /api/v1/intents/{code}/knowledge`。校验类知识会出现在运行时配置的 `validation_sets`。

## 6. 工具中心

平台只登记调用方式，不代使用方在线上执行，也不下发第三方密钥。

### 6.1 工具目录

列表默认每页 20 条，可改为 50 / 100。筛选在服务端执行，可按以下条件组合：

- 来源：全部 / 外部 / 平台内置
- 类型：全部 / API 接口 / MCP / CLI 命令 / 技能 / 工作流
- CLI 命令包、业务分组
- 状态；以及按名称、编码、描述搜索

描述单元格最多显示两行，超出省略，悬停可看全文。

「＋ 注册工具」按类型显示字段：API 接口、MCP 服务、CLI 命令、技能、工作流。写操作打开「需确认」（`confirm_required`）。外部工具可在控制台删除；开放接口只能停用。MCP 须先登记服务，保存后同步 `tools/list`（先预览再应用）；意图只关联其中的子工具，不能整体关联一个服务。技能包上传含 SKILL.md 的文件夹或 zip。工作流可从 Dify / Coze 同步入参（临时密钥不落库）。

「测试调用」：所有角色可看请求预览；真实执行仅管理员，写操作必须勾选确认。测试依赖运行环境已安装并登录对应 CLI 或已备好凭据；失败先查环境，再查工具登记。

大批量从某个 CLI 的官方目录登记命令，控制台目前没有通用的「一键导入」按钮，需要在部署环境用相应的导入脚本（幂等、先备份）。这不是某个业务空间的必做步骤。

### 6.2 给意图绑定工具

仅处理方式为「工具与知识流程」时显示关联入口。

在意图编辑里：先选类型（CLI 可再选命令包 / 业务分组），再在「选择工具」的输入框里按名称、编码或描述搜索。下拉列表限高，滚到底继续加载，已关联的会标明且不可再选。不要一次把全部工具加载进页面。

入参映射 `param_map` 的来源只能是 **槽位 / 常量 / 上下文**。控制台「上下文」当前可选值为 `session_id`、`buyer_id`、`order_id`、`sku`（这是界面上的固定列表，不是空间级预设参数；实际值仍由使用方从会话注入）。文件类入参只能映射到「文件 / 图片」槽位。技能不做入参映射。工作流必填入参若已有默认值，可以不映射。MCP 必须下钻到子工具。

也可用持有 `意图:写` 的 Key（不需要 `工具:写`）：

```http
POST /api/v1/intents/{code}/tools
Authorization: Bearer ipk_xxx
X-Space-Id: {space_id}
Idempotency-Key: bind-1
Content-Type: application/json

{
  "tool": "inventory_lookup",
  "param_map": {
    "sku": {"source": "槽位", "value": "sku"}
  },
  "dry_run": true
}
```

已绑定同一工具时，这次提交会替换映射。解绑：`DELETE /api/v1/intents/{code}/tools/{tool}`。绑定前建议先 `dry_run`。不要把尚未验收的探针工具绑到已启用的真实意图上。

### 6.3 用 API Key 注册工具（可选）

持有 `工具:写` 时，可用 `POST /api/v1/tools` 按 `name` 幂等创建或更新（先 `dry_run=true`）。`name` 为小写字母开头，只含小写字母 / 数字 / 下划线。同等 MCP 工具为 `register_tool`、`update_tool`、`disable_tool`。登记 MCP 子工具请先 `POST /mcp-servers` 再同步，不要用 `type=mcp` 单独建一条子工具。

工具一旦注册就是全平台可见的。Key 是否绑定某空间，不影响注册本身，只约束「把工具绑到哪个空间的意图」。开放接口不能删除工具，只能 `POST /tools/{name}:disable`。

常见错误：403 `SCOPE_FORBIDDEN`（缺写权限）、403 `SPACE_FORBIDDEN`（绑工具时空间不在范围）、403 `BUILTIN_READONLY`（试图改内置工具）、409 `IDEMPOTENCY_CONFLICT`（同一幂等键用于不同请求体）、422（字段或模板校验失败）。响应里不会返回 HTTP 密钥。

## 7. 用户与审计

左下角「用户与审计」（仅管理员）。

- 用户：新建控制台账号，角色为管理员 / 编辑 / 只读；可改角色、停用、重置密码。修改后该用户已登录会话立即失效。系统至少保留一个启用的管理员。
- 审计日志：记录控制台写操作以及开放接口、MCP 的调用。可按对象类型筛选。接口：`GET /api/admin/users`、`POST /api/admin/users`、`PATCH /api/admin/users/{uid}`，`GET /api/admin/audit`。

## 8. 配置时不要绕开的限制

- **没有空间级运行参数。** 不能在平台上为某个空间预置默认的业务入参。工具要求从会话注入的值（例如某个空间的店铺标识），由使用方从自己的上下文提供。
- **平台没有开放的识别接口。** 控制台的单句测试只给运营自测，使用方必须在本地识别。
- **工具结果没有通用的输出字段映射。** 除工作流的 `output_mapping` 外，平台不会告诉 Bot 该从返回值里取哪个字段来组织回复，需要写在知识或工具说明里。
- **开放接口 `GET /api/v1/tools` 没有分页。** 工具数量很大时，不要让维护型 AI 一次拉取完整目录；在控制台用筛选和搜索，或按名称读取单条。
- **图文库的图片导入暂不做 OCR。**
- **修改槽位定义不会提升空间版本。** 使用方可能仍缓存着旧的默认追问，需要时请提醒对方重新拉取，或通过编辑一条已启用意图来提升版本。

## 9. 已知问题（修复前请按此工作）

1. **转人工、固定话术、让 AI 自由发挥这三种意图目前无法启用。** 启用校验固定要求「至少关联 1 条知识或 1 个工具」，但这三种又不允许绑定，所以只能停在草稿或停用，不会进入运行时配置。未匹配或超限时的处理，请先配置**空间兜底**。意图上仍可先把处理方式存成草稿，等此问题修复后再启用。
2. **新建空间的默认兜底按空间 ID 写死。** 只有空间 ID 为 `cs` 时默认转人工，其他新空间默认让 AI 自由发挥。建好空间后，请到「空间设置」按该业务的实际需要改一次并保存，不要假设平台会按业务类型自动选择。
