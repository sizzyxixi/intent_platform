# 使用方接入指南

> 读者：**你**——要利用本平台的意图识别和工具调用，完成业务的 AI、Bot 或业务系统。
> 运营如何配置空间、意图、知识、工具和 API Key，见同目录《运营方配置手册》。字段细节以 `openapi.yaml` 为准。
> 本文只需**只读** API Key（`意图:读`、`知识:读`、`工具:读`）。文中示例来自生产环境 1688 智能客服空间（`cs`），接口形态已在 `http://intent.47.86.15.93.sslip.io` 核对。文档里的 `ipk_xxx` / `ipk_…` 只表示 Key 的格式，**不是**能用的密钥。

## 结论：你要做的事

1. 向运营要一个只读 API Key，按第 1 节放到约定位置并自检。
2. 定期拉取 `GET /api/v1/runtime-config`，只使用其中**已启用**的意图。
3. 在你这边做识别（平台没有「识别意图」接口），按空间设置处理澄清、追问和最终动作。
4. 用知识做参考和校验，按绑定关系组装并调用工具；写操作先确认。
5. 调用西之月 CLI 前必须已登录，且已有 `shop_id`；平台目前不保存默认店铺 ID。

## 你从平台得到什么

平台把一个 Bot 需要的三样东西放在一起：**意图**、**知识**、**工具**。一次 `runtime-config` 就拿到当前空间线上要用的全部配置。

```
业务空间 space（例：cs = 1688 智能客服，编码前缀 B）
├─ 分类、已启用意图（描述、例句、槽位、关联的知识与工具）
├─ 槽位定义、空间设置 recognition（阈值、澄清、追问、重试、最终动作）
├─ validation_sets（校验知识全文）
└─ tools / mcp_servers（被已启用意图用到的工具定义，不含密钥）
```

几条不变的事实：

- 只有状态为「启用」的意图会出现在运行时配置里。
- 平台只登记工具怎么调；**线上调用工具的是你**，凭据在你的运行环境里，平台不下发密钥。
- 平台**没有** `/recognize` 之类的识别接口。识别算法由你决定，语料（描述、例句、阈值）由平台提供。
- 每个空间有一个 `version`，影响线上的改动都会 +1；用 `since_version` 和 `ETag` 做增量。

生产地址：

| 项 | 生产环境 | 本地开发 |
|---|---|---|
| 平台地址 | `http://intent.47.86.15.93.sslip.io` | `http://127.0.0.1:8000` |
| API Base | `http://intent.47.86.15.93.sslip.io/api/v1` | `http://127.0.0.1:8000/api/v1` |
| MCP | `http://intent.47.86.15.93.sslip.io/mcp`（`POST`，JSON-RPC 2.0） | `http://127.0.0.1:8000/mcp` |

意图类接口带 `X-Space-Id`（或 `?space=`）；不传时用 Key 绑定的第一个空间。知识库和工具接口是全局的，不需要空间头。

## 1. 初始化

### 1.1 向运营要 API Key

你不创建 Key。请运营（管理员）在控制台「工具中心 › 接入与密钥」为你新建一把只读 Key，绑定你要服务的空间（1688 智能客服是 `cs`），权限勾选 `意图:读`、`知识:读`、`工具:读`。完整 Key 只显示一次，前缀是 `ipk_`。

若还需要往平台写意图或导入知识，那是运营侧的工作，要用带「写」权限的 Key，见《运营方配置手册》。

### 1.2 把 Key 放到约定位置

按这个顺序查找，**找到第一个就用，不要再往下搜**：

1. 环境变量 `INTENT_PLATFORM_API_KEY`。同时读取（若已设置）`INTENT_PLATFORM_BASE_URL`、`INTENT_PLATFORM_SPACE`。
2. 配置文件 `~/.intent-platform/config.json`，权限必须是 `600`：

```json
{
  "base_url": "http://intent.47.86.15.93.sslip.io",
  "api_key": "ipk_…",
  "space_id": "cs"
}
```

未设置 `INTENT_PLATFORM_BASE_URL` 时用生产地址；未设置 `INTENT_PLATFORM_SPACE` 时用配置文件里的 `space_id`，再缺省为 `cs`。

**如果两处都没有 Key：立即停止，向人要，或请运营按上面的路径创建并写入约定位置。禁止在 `~/.xclaw/`、`~/.workbuddy/`、插件目录、项目仓库或其他目录里搜索 `ipk_`。那些位置即使出现类似字符串，也不是本平台的 API Key。**

### 1.3 自检

先装载配置，再请求 `GET /api/v1/spaces`。成功后再做别的调用。

```bash
if [ -z "$INTENT_PLATFORM_API_KEY" ] && [ -f "$HOME/.intent-platform/config.json" ]; then
  eval "$(python3 - <<'PY'
import json, os, shlex
d = json.load(open(os.path.expanduser("~/.intent-platform/config.json")))
print("export INTENT_PLATFORM_API_KEY="+shlex.quote(d["api_key"]))
print("export INTENT_PLATFORM_BASE_URL="+shlex.quote(d.get("base_url") or "http://intent.47.86.15.93.sslip.io"))
print("export INTENT_PLATFORM_SPACE="+shlex.quote(d.get("space_id") or "cs"))
PY
)"
fi
: "${INTENT_PLATFORM_BASE_URL:=http://intent.47.86.15.93.sslip.io}"
: "${INTENT_PLATFORM_SPACE:=cs}"
if [ -z "$INTENT_PLATFORM_API_KEY" ]; then
  echo "未找到 API Key。请运营在控制台「工具中心 › 接入与密钥」创建，写入环境变量 INTENT_PLATFORM_API_KEY 或文件 ~/.intent-platform/config.json（chmod 600）。不要在其他目录搜索。"
  exit 1
fi

curl -sS -D - "$INTENT_PLATFORM_BASE_URL/api/v1/spaces" \
  -H "Authorization: Bearer $INTENT_PLATFORM_API_KEY"
```

Key 绑定了 `cs` 且具备 `意图:读` 时，成功是 **200**，例如：

```json
[{"space_id": "cs", "name": "1688 智能客服", "description": "1688 店铺询盘的智能客服试点",
  "bot": "客服 Bot（吴钢）", "code_prefix": "B"}]
```

返回的只是该 Key **绑定的空间**。每个响应带 `X-Request-Id`。

| 结果 | 含义 | 你该怎么做 |
|---|---|---|
| 200 且列出预期空间 | Key 有效 | 进入第 2 节或第 5 节 |
| 401 `UNAUTHORIZED`，文案含「缺少 API Key」 | 没带 `Authorization: Bearer ipk_…`，或格式不对 | 检查环境变量 / 配置文件和请求头；不要换路径反复试 |
| 401 `KEY_REVOKED` | Key 已被吊销 | 停止，请运营重新创建 |
| 403 `SPACE_FORBIDDEN` | `X-Space-Id` 不在绑定范围内（例如绑定了 `cs` 却传 `mc`） | 改用绑定的空间，或请运营给 Key 加上该空间 |
| 403 `SCOPE_FORBIDDEN` | 缺少该接口所需权限 | 停止，说明 `details.required`，请运营补权限 |

### 1.4 西之月 CLI 登录（调用 xclaw 工具前）

cs 绑定的外部工具主要是 `xclaw-cli`。调用前，运行环境必须先具备凭证，任选一种：

- 执行 `xclaw-cli auth login`（UMC OAuth 登录 MoonClaw）；或
- 设置环境变量 `XCLAW_UMC_TOKEN`

工具定义里写的是 `cli.auth_env = XCLAW_UMC_TOKEN`、`cli.login_command = xclaw-cli auth login`。可用 `xclaw-cli auth status --json` 查看登录状态。未登录就执行，属于运行环境问题：转人工并记录，不要向用户索要账号或 token。

### 1.5 店铺 ID（`shop_id`）与当前限制

cs 的 17 个已启用意图里，有 15 个带槽位 `shop_id`（显示名「店铺」）。绑定的西之月命令（如 `xclaw-cli platform alibaba product get --shop-id {shop_id} …`，以及 `platform alibaba product list`）都要这个参数。没有 `shop_id` **不要调用**这些命令。

`shop_id` 从哪里来，按这个顺序：

1. **会话上下文（设计预期）**：询盘来自某一家已授权的 1688 店铺时，由接入层（IM / 客服工作台）把该店铺的 ERP 店铺 ID 注入会话，你写入槽位 `shop_id`。槽位默认追问是「（不向买家追问：由 Bot 按会话所属的 1688 店铺带入 ERP 店铺 ID）」，不要把这句话发给买家。
2. **本平台目前没有「空间级运行时变量」或「默认店铺 ID」。** 运行时配置里也没有这个字段。不要臆造相关接口。
3. 会话里没有时：向使用你的人要这个店铺的 ERP 店铺 ID。
4. 若已经登录西之月，可以列出已授权店铺供人挑选（有多家时不要自己猜）：

```bash
xclaw-cli mall platform-store shop list --platform-code alibaba --json
```

这条没有必填参数。也可以用 `xclaw-cli operate customer shop alibaba get --page 1 --size 20 --json`（`page`、`size` 必填）。

不要用 `xclaw-cli platform alibaba product list` 去「发现店铺」：它是「指定店铺的商品列表」，本身就必填 `--shop-id`。

## 2. 运行时循环

### 2.1 拉取并缓存运行时配置

```bash
curl -sS -D - "$INTENT_PLATFORM_BASE_URL/api/v1/runtime-config?since_version=0" \
  -H "Authorization: Bearer $INTENT_PLATFORM_API_KEY" \
  -H "X-Space-Id: $INTENT_PLATFORM_SPACE"
```

第一次或本地没有缓存时用 `since_version=0`。成功是 **200**，响应头有 `ETag: "cs-v61"`（版本号会随配置变化增加）。`space` 是对象 `{"id","name","bot"}`，不是字符串。

当前生产（已核对）：`version` 为 **61**，17 条已启用意图、4 个被引用的工具、18 组校验知识。把整份配置缓存下来，记下 `version`。再用同一个版本请求，没变化会返回 **304**，响应头仍是该 `ETag`，没有 body。建议定时轮询（如每分钟一次），不要每轮对话都拉；版本变了要替换缓存并清空识别缓存。

顶层字段：`space`、`version`、`generated_at`、`recognition`、`taxonomy`、`slots`、`intents`、`validation_sets`、`tools`、`mcp_servers`。

### 2.2 识别、澄清与槽位

每一轮对话按 `recognition` 处理：

1. **识别**：用每个已启用意图的 `description` 和 `examples` 给用户原话打分，得到 Top3 及置信度。算法由你决定。
2. **阈值判定**：Top1 ≥ `threshold`（cs 为 0.6）→ 命中。否则取置信度 ≥ `candidate_min`（0.3）的候选（最多 `max_candidates` 个），用 `clarify_prompt` 请用户选；没有候选 → 执行最终动作。
3. **澄清**：用户选中即命中；澄清超过 `max_clarify` 次仍不明确 → 最终动作。
4. **槽位**：从对话和上下文抽取。缺必填槽位时用该槽位的 `ask` 追问；同一槽位追问超过 `max_slot_ask` 次 → 最终动作。`ask` 以「（不向买家追问：…）」开头的槽位，是给你或人工填的，不要拿去问用户。

cs 还有校验知识 `kb_cs_conf`（整篇关联），你必须照做，例如：置信 0.60～0.85 或缺关键槽位时只问 1 个澄清问题，不得调用改价等成交类工具；低于 0.60 或投诉则转人工。

### 2.3 检索知识

- **参考（reference）**：回答或生成时的依据。按意图 `knowledge` 里的 `kb_id` / `doc_id` / `chunk_id` 读取，或按需检索。
- **校验（validate）**：硬约束。全文已在 `validation_sets` 里，生成后逐条比对。`chunk_id="*"` 表示整篇都是校验项。不通过就改写，改写不了就执行最终动作。

指定知识库检索：

```bash
curl -sS "$INTENT_PLATFORM_BASE_URL/api/v1/kbs/kb_cs_reply/search" \
  -H "Authorization: Bearer $INTENT_PLATFORM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query":"改价","top_k":2}'
```

成功是 **200**。每一项含 `score`、`kb_name`、`doc_name`、`chunk`（`chunk_id`、`doc_id`、`content`、`cells`、`effective_tags`、`linked_intents`；`kb_id` 在 `chunk` 内）。检索「改价」时，第一条为 `RULE-13`，禁止项包括「未改先说已改好」。跨库检索用 MCP `search_knowledge`（不传 `kb_id`）；REST 没有跨库检索。也可 `GET /api/v1/kbs/{kb_id}/chunks?doc_id=…&q=…`。

### 2.4 解析并调用绑定的工具

对 `param_map` 里每个入参：`source=槽位` 取槽位值，`source=常量` 直接用 `value`，`source=上下文` 取会话上下文（`session_id`、`buyer_id`、`order_id`、`sku`）。**必填入参拿不到值时不要调用**。未映射的选填入参不传。然后到顶层 `tools[]` 按 `name` 找定义，按 `type` 执行：

| type | 你怎么调用 |
|---|---|
| `cli` | 在你的运行环境执行 `cli.command_template`：把 `{参数名}` 换成入参；选填参数为空时，连同它前面的 `--选项` 一起去掉；按参数数组执行，不拼 shell 字符串。凭据放在 `cli.auth_env`，或预先用 `cli.login_command` 登录。`output_format=json` 时把 stdout 解析为 JSON |
| `mcp` | 按 `mcp_server` 建立连接，调用 `tools/call`；凭据按 `credentials[]` 从你环境里名为 `env` 的变量取值 |
| `http` | 按 `method` + `url` 发请求；凭据由你托管 |
| `workflow` | 按 `workflow.platform` 调用 Dify / Coze / 通用 HTTP，令牌取 `workflow.auth_env` |
| `skill` | `GET /api/v1/tools/{name}/skill-package` 下载 zip，按其中的 SKILL.md 执行；技能没有入参映射，把抽到的槽位作为上下文交给它 |
| 平台内置（`source=builtin`） | 调本平台接口，带你自己的 API Key；按空间的带 `X-Space-Id` |

`confirm_required=true` 表示会改动外部数据。调用前必须先得到确认：面向用户的场景要用户明确同意；客服类场景按空间规则由人工确认（cs：输出草稿，由人点发送）。没有确认就不调用。cs 中需确认的包括 `xclaw_platform_alibaba_trade_order_modifyorderprice_call`（改价，金额单位是分）等。不要对用户说「已改好」，除非工具返回成功。

工具报错或超时，最多重试 `tool_retry` 次，仍失败则澄清或走最终动作。绝不编造库存、价格、交期、物流、退款结果。

### 2.5 最终动作

`recognition.final_action`：`handoff_human` 转人工；`general_assistant` 交给通用助手；`decline` 回复 `final_message`。识别、澄清、追问、工具失败任一环节超限，都执行它。cs 的最终动作是转人工。

## 3. 用 MCP 代替 REST

同一把 Key，请求 `POST {Base URL}/mcp`。方法：`initialize`、`ping`、`tools/list`、`tools/call`。

只读相关工具：`list_intents`（还可 `view=taxonomy` / `slots` / `spaces` / `recognition`）、`get_intent`、`search_knowledge`、`list_tools`。写工具 `upsert_intents`、`import_knowledge` 需要写权限，那是运营侧的事。

客户端配置示例（Key 不要写进权限过宽的文件；与 `~/.intent-platform/config.json` 同样按 600 保密）：

```json
{ "mcpServers": { "intent-platform": { "url": "http://intent.47.86.15.93.sslip.io/mcp",
    "headers": { "Authorization": "Bearer <INTENT_PLATFORM_API_KEY>", "X-Space-Id": "cs" } } } }
```

生产上 `initialize` 返回 `serverInfo.name=intent-platform`、`version=0.17.0`。完整 inputSchema 见 `AI接入说明.md` 第 9 节。

## 4. 错误码（使用方常见）

| HTTP | 常见 code | 你下一步 |
|---|---|---|
| 401 | `UNAUTHORIZED`（缺少 API Key）、`KEY_REVOKED` | 按第 1.3 节处理；不要到其他目录搜索 Key |
| 403 | `SCOPE_FORBIDDEN`、`SPACE_FORBIDDEN` | 不重试；说明缺权限或空间不对 |
| 404 | `INTENT_NOT_FOUND`、`KB_NOT_FOUND`、`CHUNK_NOT_FOUND`、`TOOL_NOT_FOUND` 等 | 重新列表查询确认 ID |
| 429 | `RATE_LIMITED` | 按 `Retry-After` 等待（每个 Key 每分钟 60 次） |

错误体统一为 `{code, message, details, request_id}`。

## 5. 第一次调用（cs 端到端）

以下每一步都在生产环境用只读 Key 核对过（工具的真实 CLI 执行还依赖第 1.4、1.5 节的登录和店铺 ID，文档没有编造执行结果）。

**第 1 步：自检。** 按 1.3 调用 `GET /api/v1/spaces`，得到 200 后再继续。

**第 2 步：拉运行时配置。** `GET /api/v1/runtime-config?since_version=0`，带 `X-Space-Id: cs`，得到 200、`version: 61`、`ETag: "cs-v61"`。再用 `since_version=61` 请求，得到 304。

**第 3 步：识别。** 用户说「拍好了帮我改下价」——这是意图 `B.MID.CHANGE_ORDER`（售中改价改单）的标准例句。若 Top1 是它且置信度 ≥ 0.6，即命中。`order_id` 必填，向买家要订单号；`shop_id` 等「不向买家追问」的槽位按第 1.5 节处理。

**第 4 步：取知识。** 校验知识已在 `validation_sets`（如 `kb_cs_reply` 的 RULE-13、`kb_cs_conf` 整篇）。再检索：`POST /api/v1/kbs/kb_cs_reply/search`，body `{"query":"改价","top_k":2}`，200，第一条即 RULE-13，`linked_intents` 含 `B.MID.CHANGE_ORDER`。

**第 5 步：解析工具。** 该意图当前绑定：

- `xclaw_platform_alibaba_product_get`（查询商品，读）：`--shop-id` ← 槽位 `shop_id`，`--product-id` ← 槽位 `offer_id`，`--web-site` / `--scene` 为常量 `1688`
- `xclaw_platform_alibaba_trade_order_modifyorderprice_call`（改价，`confirm_required=true`）：还需要 `order_id`、`carriage`、`entry_discounts`；没有人工确认不得调用

**第 6 步：调用。** 入参齐全、已登录西之月、已有 `shop_id` 时，查询商品的 argv 为：

```
["xclaw-cli","platform","alibaba","product","get","--shop-id","<ERP店铺ID>","--product-id","<商品ID>","--web-site","1688","--scene","1688","--json"]
```

缺 `shop_id` 或未登录就不要执行，向使用你的人或接入层要，不要编造。改价还必须先确认，金额单位是分。

## 6. 底线

- 不编造库存、价格、交期、物流、退款结果；工具没给就不说。
- 写操作先确认；没确认不调用 `confirm_required=true` 的工具。
- 不向用户索要账号、密码、token、cookie。本平台 API Key 只从第 1.2 节约定位置读取，找不到就停下来问人。
- 只使用已启用意图；不要把运行时配置当成「整理意图」的依据。
